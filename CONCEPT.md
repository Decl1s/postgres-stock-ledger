# Концепция: мини-склад на PostgreSQL

Дата: 20.10.2026, версия 0.1.0. Учебный проект, не заявление о коммерческом опыте.
Новый основной инструмент — PostgreSQL; предыдущий проект изучал Prefect.

Цель: показать атомарную загрузку небольшого CSV, две границы идемпотентности
(партия и событие), проверку остатка и конкурентные записи. Пользователь получает
воспроизводимое демо с итогом BOOK=7, PEN=16, BAG=3 и доказанным откатом ошибок.

Выбор среды: уже установленный PostgreSQL 16.15, локальный Python 3.12 и Psycopg 3.3.6.
Демо стартует в новом отдельном кластере с аутентификацией и завершает его после работы.
Никакие системные службы, чужие базы и настройки аккаунтов не изменяются.

Модель узкая: один склад, целые единицы товара, без дат, цен, резервов и нескольких
мест хранения. Положительная delta — приход, отрицательная — расход. Конечный
остаток всей партии неотрицателен. Проверка промежуточной последовательности
событий не требуется; в CSV нет времени события.

Критерии готовности: COPY staging → проверки → INSERT в одной транзакции;
точный дубль не удваивает остаток; конфликт ID отклоняется; ошибка после INSERT
откатывает и партию, и события; две конкурирующие загрузки не обходят проверку;
входы синтетические; зависимости закреплены; русские комментарии, карта кода,
задания и подробный конспект готовы; архив собран по явному списку.

Не входят: распределённая очередь, автоматический retry, роли промышленного сервера,
миграции между версиями, высокая конкурентность и постоянное хранение демо-кластера.
Создание внешнего репозитория, загрузка исходников, CI и релиз оцениваются раздельно
по фактически подтверждённому состоянию в VALIDATION.md.
