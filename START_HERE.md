# Начни здесь: что где и как редактировать

Первый запуск — `python -m stock_ledger demo` интерпретатором из .venv.
Полные команды установки и Windows-вариант находятся в README.
Временный сервер требует разрешённых локальных сокетов и установленного PostgreSQL 16.

## Карта кода

| Файл / функция | Ответственность | Что здесь менять |
| --- | --- | --- |
| stock_ledger/examples.py / CASES | Фиксированные синтетические события | Учебные количества и новые примеры |
| stock_ledger/core.py / read_csv | UTF-8, заголовок, типы и пределы | Новые поля входа и допустимые значения |
| core.py / initialize | Явное создание своей схемы, проверка версии | Только осмысленное развитие схемы |
| core.py / load_batch | LOCK → COPY → проверки → вставка → COMMIT | Политику повторов, конфликтов, проверки остатка |
| core.py / snapshot | Согласованный отчёт несколькими SELECT | Новые агрегаты отчёта |
| stock_ledger/sql/schema.sql | Таблицы, PK/FK/CHECK и view остатков | Схему и ограничения БД |
| sql/stage.sql | Промежуточную таблицу входа | Staging-контракт |
| sql/insert.sql | Массовую вставку уникальных событий | Способ применения проверенных данных |
| stock_ledger/lab.py | Жизненный цикл отдельного временного сервера | Поиск PG_BIN и управление кластером |
| stock_ledger/__main__.py | Аргументы, команды и демонстрацию | Пользовательский CLI |
| scripts/workshop.py | Загрузку выбранных файлов по порядку | Учебный эксперимент, не бизнес-правила |
| tests/test_contract.py | Проверки без сервера | Форму CSV и поведение CLI |
| tests/integration.py | Настоящие транзакции и конкуренцию | Проверки новых гарантий БД |
| scripts/check_public.py и package_release.py | Проверку состава исходников, ZIP и SHA-256 | Упаковку и разрешённый список |
| PUBLIC_FILES.txt | Явный состав публикации | Только новые исходники/документы, не рабочие данные |
| pyproject.toml, uv.lock | Прямую зависимость и полный закреплённый набор | Зависимости через uv, с повторной проверкой |
| .vscode | Готовые задачи, Python и F5 | Частые локальные команды и точки запуска |

Папка workspace хранит твои CSV/отчёты и временный runtime. Она не входит в Git.
.venv/.tools/.cache восстановимы; их код не нужно редактировать, чтобы поменять склад.
NOTES объясняет понятия; DECISIONS — выбор и цену решений; EXERCISES — задания;
VALIDATION — что действительно запущено, а что только подготовлено.

## Порядок чтения

1. В examples найди приход E0001 BOOK +10 и расход E0004 BOOK -3.
2. В read_csv посмотри, когда строка становится int и вычисляется sha256.
3. В load_batch найди `with conn.transaction()`: все принятые изменения должны
   оказаться внутри этой границы. Возврат функции выйдет через COMMIT, исключение — ROLLBACK.
4. Проследи staging, поиск конфликтов и INSERT. Затем найди проверку quantity < 0.
5. В snapshot увидишь BOOK=7; повторное E0002 не добавило ещё 20 единиц PEN.

## Как потыкать в IDE

В Terminal → Run Task есть подготовка CSV, автономное демо, быстрые тесты,
интеграция и проверка публикации. Для выходной папки редактор запросит новое имя:
предыдущие файлы не перезаписываются. Новые папки выбираются через --output.

Открой core.py и поставь F9 на строке `inserted = len(conn.execute(...))`.
Выбери отладку «Демо: транзакции PostgreSQL», нажми F5. F10 выполнит вставку.
На ветке failure исключение появится после INSERT, а demo сравнит снимок с прежним.
Отдельный запуск отладки интеграции позволяет остановиться в конкурентном тесте;
долгая пауза в удерживающем блокировку потоке может превысить короткий lock_timeout.

Для изменения CSV выполни sample один раз, затем выбери файлы для workshop:

```bash
.venv/bin/python scripts/workshop.py workspace/input/receipts.csv workspace/input/dispatch.csv --output workspace/experience-1 --repeat-first
```

Измени расход BOOK с -3 на -8 и запусти с --output workspace/experience-2.
Получишь BOOK=2. Измени на -30: в steps.json вторая партия будет отвергнута,
остатки останутся от первой партии, общий код выхода — 1. Сервер после опыта остановится.
Каждый новый запуск workshop начинает с пустой базы; повтор внутри этого опыта
демонстрирует --repeat-first, а постоянную историю дают команды с STOCK_DSN.

## Аргументы и их смысл

| Аргумент/переменная | Что означает |
| --- | --- |
| demo --output | Новая папка CSV/сводки; база временная |
| sample --output | Новая папка пяти редактируемых синтетических входов |
| load --input | Один явно выбранный CSV, не вся домашняя папка |
| load --batch | Ключ логической партии для безопасного повтора |
| load --fail-before-commit | Контролируемое исключение после вставки, чтобы увидеть откат |
| STOCK_DSN | Подключение только для init/load/report; не коммить и не печатай пароль |
| PG_BIN | Папка уже установленного PostgreSQL 16 с initdb и pg_ctl |
| STOCK_TEST_DSN | Только интеграционные тесты CI в отдельной базе stock_test |
| workshop files | Явный порядок файлов, каждый в своей транзакции |
| workshop --repeat-first | Повтор первой партии в том же сервере с прежним ключом |

Хочешь другое складское правило — сначала опиши вход и ожидаемый остаток, затем
поменяй проверку/SQL и добавь интеграционный пример. Если меняется схема, продумай
миграцию версии: новая библиотека или красивое имя таблицы сами этого не решают.
